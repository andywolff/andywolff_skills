## Android Embedder & Graphics Engine

### API Design & Mock Compatibility
* **Rule**: When changing native embedder (JNI/Obj-C) signatures, retain legacy signatures as fallbacks.
* **Rationale**: Modifying signatures breaks existing unit test mock stubs (like Mockito) and downstream plugin dependencies that rely on the legacy signature.

---

### Test Canvas Texture Usage for Emulated Readbacks
* **Rule**: When creating mock test canvases in unit tests to emulate
  non-framebuffer-fetch devices (such as OpenGLES) on Metal or Vulkan, ensure
  the onscreen `TextureDescriptor` includes `TextureUsage::kShaderRead`
  whenever readback is requested (`requires_readback = true`). However, for
  transient MSAA attachments (`StorageMode::kDeviceTransient`), set `usage`
  strictly to `TextureUsage::kRenderTarget`.
* **Rationale**: Backdrop flipping and advanced blend emulation read from the
  render target texture in shaders via `TextureContents`. Without
  `TextureUsage::kShaderRead`, graphics API validation layers assert during
  test execution. Conversely, setting `kShaderRead` (sampled) on transient
  textures violates Vulkan VUID-VkImageCreateInfo-usage-00963.

---

### macOS MoltenVK Dynamic Library Loading in Test Runners
* **Rule**: When executing host unit tests (like `impeller_unittests`) with the
  Vulkan backend on macOS, supply `DYLD_FALLBACK_LIBRARY_PATH="$VULKAN_SDK/lib"`
  if the Vulkan dynamic loader is not installed globally in system library paths.
* **Rationale**: GLFW (`glfwVulkanSupported()`) and Impeller resolve
  `libvulkan.dylib` via `dlopen`. Setting `DYLD_FALLBACK_LIBRARY_PATH` directs
  dynamic linking to the SDK without overriding system Metal or OS libraries.

---

### Vulkan Memory Type Selection
* **Rule**: When selecting a memory type index for Vulkan allocations, iterate
  through `VkPhysicalDeviceMemoryProperties.memoryTypes` and verify that
  `(propertyFlags & required_flags) == required_flags`. Avoid bitwise ANDing
  multiple distinct `VkMemoryPropertyFlagBits` together against
  `VkMemoryRequirements.memoryTypeBits`.
* **Rationale**: `VkMemoryRequirements.memoryTypeBits` is an index bitmask into
  the physical device memory types array, not a combination of property flags.
  ANDing multiple property flags (such as `HOST_VISIBLE` and `HOST_COHERENT`)
  directly results in zero, leading to undefined behavior with `__builtin_ctz`
  or invalid allocation indices.

---

### Asynchronous Test Snapshot Awaiting
* **Rule**: In framework and engine unit tests, ensure all asynchronous helper
  calls that perform raster snapshots (`toImage`) are explicitly `await`ed before
  the test callback finishes.
* **Rationale**: Unawaited snapshot loops run synchronously within the event loop
  tick, triggering dozens of snapshots in rapid succession. When host buffer
  capacity is reset per snapshot, rapid unawaited resets cycle through the
  fixed-size host buffer arena and overwrite uniform and vertex data while
  earlier asynchronous GPU command buffers are still executing.

### Offscreen Render Target Cache Lifecycle & Memory Management
* **Rule**: Manage offscreen render target caches by purging entries between
  test runs and under memory pressure, rather than tracking GPU completion fences.
* **Rationale**: Metal driver hazard tracking and Vulkan single-queue submission
  order with render pass pipeline barriers prevent GPU race conditions in real
  applications. Order dependencies in test environments stem from leaked cache
  state across consecutive tests, which is resolved by purging the cache at
  test boundaries.

---

### Offscreen Render Target Cache Pixel Format Matching
* **Rule**: Include the color attachment pixel format in `RenderTargetConfig`
  comparisons and hash keys within `RenderTargetCache`.
* **Rationale**: In applications with wide color gamut enabled (such as Display
  P3 on macOS/iOS), the onscreen window surface allocates wide-gamut textures
  while subpasses or raster caches may request standard sRGB textures of the
  exact same dimensions. Omitting pixel format from the cache key causes
  mismatched textures to be recycled, triggering blit validation failures.

### Wide-Gamut Golden Screenshot Quantization
* **Rule**: Do not rely on Skia Gold or standard PNG golden image comparators to verify 10-bit color depth or out-of-gamut extended range coordinates. Inspect raw `rawExtendedRgba128` floating-point pixel buffers directly for lossless numerical verification.
* **Rationale**: Skia Gold digests and compares 8-bit per channel PNGs. Metal golden screenshotters convert 10-bit wide-gamut render targets (`kB10G10R10A10XR`) to standard 8-bit DeviceRGB PNGs via CoreImage (`CIContext.createCGImage`), quantizing and clamping extended values prior to upload.

### Gradle Execution Path Resolution
* **Rule**: When running `./gradlew` programmatically:
  - Always set the working directory to the `android/` subdirectory (containing `settings.gradle`), NOT the Flutter package root, to prevent Gradle from aborting with `does not contain a Gradle build`.
  - Resolve the `./gradlew` executable path absolutely to prevent path mismatches relative to the working directory.

### Local Golden Test Validation
* **Rule**: To validate golden comparisons locally without Skia Gold, first
  generate reference baseline images in `test_driver/goldens/` by running
  `flutter drive` with the environment variable `UPDATE_GOLDENS=1` active,
  otherwise the subsequent instrumented APK will fail to find and load
  comparator reference images.
* **Local Linter Masking**: Local `analysis_options.yaml` files (e.g., generated
  dynamically by `flutter create` or plugins) can override the repository's root
  `analysis_options.yaml` and mask static analysis errors during local
  `flutter analyze` runs. Deleting them ensures repo-wide strict rules are
  enforced correctly.

### Testing Platform Views: Native Draw Synchronization
* **Best Practice**: When writing platform view integration/smoke tests, avoid using a simple frame-delay loop (`WidgetsBinding.instance.endOfFrame`) before screenshots as they are highly susceptible to race conditions (blank/black overlays). Instead, await a native draw event dispatched from the native view itself (e.g., by subclassing the native view and overriding `onDraw(Canvas)`).
* **Reference**: See the synchronized text view implementation in `android_hardware_smoke_test` (introduced in PR #189151).
* **Timeout Rule**: Never add localized/arbitrary timeouts (e.g., `future.timeout()`) to asynchronous test futures; let the global test/JUnit runner timeouts handle hangs (see [Style-guide-for-Flutter-repo.md](file:///Users/awolff/Projects/andywolff/flutter-sync_composition/docs/contributing/Style-guide-for-Flutter-repo.md#L876-L886)).

---

### EGL Config Prevention & Error Recovery
* **Rule**: Explicitly set the window pixel format to `PixelFormat.RGBA_8888` in `MainActivity.onCreate` to prevent the OS from attempting to negotiate 10-bit wide-gamut formats (`101010-2`) that are unsupported or flaky on SwiftShader CPU-based graphics drivers. This is safe and does not reduce intended test coverage, as standard Android devices default to sRGB (`RGBA_8888`) and dedicated Display P3/wide gamut rendering coverage is verified by the `wide_gamut_test` suite instead.
* **AVD Error Recovery**: Process- or Activity-level restarts are insufficient when an emulator enters a broken EGL initialization state; recovering graphics rendering requires restarting or re-creating the underlying AVD process.

### Git Worktree Management
* **Preference**: Use Git worktrees when switching branches to prevent concurrent access conflicts.
* **Guidelines**: Refer to [git-worktree-management](file:///Users/awolff/Projects/andywolff/andywolff_skills/.agents/skills/git-worktree-management) for procedures on symlinking skills, checking merge status, and safely removing worktrees.

### Bootstrapping gclient in a Worktree
* **Rule**: When using Git worktrees for engine/framework development, copy the `.gclient` configuration file from the master or sibling checkout to the root of the new worktree to ensure `gclient sync` can locate the solution root.

### Pre-push Hook Scope and Stale Upstream Diffing
* **Rule**: Flutter engine's `pre-push` githook calculates changed files against `origin/master`. If `origin/master` has fallen behind `upstream/master`, the hook will attempt to format and validate all intermediate commits that landed upstream.
* **Mitigation**: Update `refs/remotes/origin/master` to match `upstream/master` (e.g. `git update-ref refs/remotes/origin/master refs/remotes/upstream/master`) or pass `--no-verify` on `git push` when pushing rebased feature branches.

## CI & CLI Tools

### Engine Compilation with `et`
* **Engine Tool (`et`)**: Use the engine tool (`engine/src/flutter/bin/et`) to compile and build targets (e.g., `et build -c android_debug_unopt_arm64`). It automatically generates build files and handles target configurations, environment variables, and toolchains cleaner than raw GN and Ninja commands.

---

### In-Flight gclient Staging Directories
* **Rule**: Treat `_gclient_*` directories in `third_party/` as active staging targets rather than stale or failed build debris. Never delete them or diagnose missing dependencies without first checking for running sync or clone processes (`pgrep -fl "gclient|git-remote"`).
* **Rationale**: `gclient` clones repositories into temporary `_gclient_<name>_<hash>` directories and atomically renames them only upon completion. Deleting staging directories while clones are in progress corrupts active network transfers and causes subsequent build tools to fail with missing dependency errors.

---

### Xcode Metal Toolchain Resolution
* **Rule**: When compiling Metal shaders (`.metal` -> `.metallib`) on macOS hosts with Xcode downloadable components where `metal` is not in the default path, set `TOOLCHAINS=Metal` to direct `xcrun` to the mounted Metal toolchain.

---

### Asynchronous Monitoring: Watch Mode over Polling
* **Rule**: When monitoring the status of any background process, PR build, or external resource, always prefer using a blocking "watch" or "collect" command (e.g., `bb collect` or event-based listeners) in a background task over periodic polling loops.
* **LUCI Build Monitoring**: Use `bb collect $(bb ls -t buildset:sha/git/<sha> flutter/try -id)` to wait for presubmit builds to finish.
* **PR Checks Watch Limitation**: Avoid using `gh pr checks <pr> --watch` on Flutter repo PRs because the `Merge Queue Guard` status check remains indefinitely in a `pending` state for draft/non-queued PRs, preventing the command from ever exiting.

### Handling Verbose CLI Outputs
* **Pitfall**: Large CLI outputs (e.g., `git log`, `bb ls`) can exceed console limits and get truncated at the top, leading to silent omission of critical logs.
* **Mitigations**:
  - Request compact outputs (e.g., `git log -n 10` or filtering fields).
  - Redirect verbose output to a file and read it incrementally using `view_file` to prevent console truncation.

---

### Jetski CLI Settings File
* **Settings Location**: Jetski CLI settings and command approval configurations are stored in `~/.gemini/jetski/cli/settings.json`.

---

### Concurrent CLI Session Token Overwrites
* **Rule**: When OAuth scopes change or backend routing flips (e.g. `ACCESS_TOKEN_SCOPE_INSUFFICIENT`), terminate older background CLI sessions across other workspaces before re-authenticating.
* **Rationale**: Lingering background CLI instances refresh credentials hourly using their original, unscoped refresh tokens and write them back to the shared macOS Keychain, clobbering updated tokens and causing new sessions to fail.

* **Handling Authentication Errors**: Never skirt around authentication problems or disable tooling configurations (such as disabling RBE or bypassing depot_tools auto-updates) when encountering credential errors. Ask the user to refresh credentials (e.g. `gcert`, `cipd auth-login`) first.
